Wickeban exposes a local MCP (Model Context Protocol) server, allowing you to manage projects and tasks from external MCP clients like Claude Desktop, Raycast, or even coding agents running within Wickeban itself.

<Note>
This page covers connecting **external MCP clients** to Wickeban's MCP server. For configuring MCP servers **within** Wickeban for your coding agents, see the [MCP Server Configuration](/integrations/mcp-server-configuration) guide.
</Note>

<Info>
Wickeban's MCP server is **local-only** - it runs on your computer and can only be accessed by applications installed locally. It cannot be accessed via publicly accessible URLs.
</Info>

## Setting Up MCP Integration

### Option 1: Using the Web Interface

This works if you're adding the Wickeban MCP server to any [supported coding agent](/supported-coding-agents) **within** Wickeban.

1. In Wickeban Settings, navigate to the "MCP Servers" page
2. In the "Popular servers" section, click on the Wickeban card
3. Click the `Save Settings` button

<Frame>
<img src="/images/vk-mcp-server-config.jpeg" alt="MCP Servers configuration page showing how to add Wickeban MCP server" />
</Frame>

### Option 2: Manual Configuration

You can manually add the MCP server to your coding agent's configuration. The exact syntax will depend on your coding agent or MCP client.

Add the following configuration to your agent's MCP servers configuration:

```json
{
  "mcpServers": {
    "wickeban": {
      "command": "npx",
      "args": ["-y", "wickeban@latest", "--mcp"]
    }
  }
}
```

## Available MCP Tools

The Wickeban MCP server provides the following tools for managing projects and issues:

### Health

| Tool | Purpose | Required Parameters | Optional Parameters | Returns |
|------|---------|-------------------|-------------------|---------|
| `ping` | Check if the Wickeban server is running | None | None | Status and version |

### Project Operations

| Tool | Purpose | Required Parameters | Optional Parameters | Returns |
|------|---------|-------------------|-------------------|---------|
| `list_organizations` | List all organisations | None | None | List of organisations with metadata |
| `list_projects` | List all projects in an organisation | `organization_id` | None | List of projects with metadata |

### Context

| Tool | Purpose | Required Parameters | Optional Parameters | Returns |
|------|---------|-------------------|-------------------|---------|
| `get_context` | Get current workspace context (only available within an active workspace session) | None | None | Project, issue, and workspace metadata |

### Issue Management

| Tool | Purpose | Required Parameters | Optional Parameters | Returns |
|------|---------|-------------------|-------------------|---------|
| `list_issues` | List issues in a project | None | `project_id`<br/>`limit` | List of issues with status |
| `search_issues` | Search issues by title (case-insensitive) | `query` | `project_id`<br/>`limit` | Matching issues |
| `create_issue` | Create a new issue | `title` | `project_id`<br/>`description` | Created issue ID |
| `create_issue_with_context` | Create an issue with structured metadata | `title` | `project_id`<br/>`summary`<br/>`repo_name`<br/>`file_path`<br/>`line_number`<br/>`git_ref`<br/>`error_output`<br/>`command` | Created issue ID |
| `get_issue` | Get issue details | `issue_id` | None | Full issue information |
| `update_issue` | Update issue details | `issue_id` | `title`<br/>`description`<br/>`status` | Updated issue information |
| `delete_issue` | Delete an issue | `issue_id` | None | Deletion confirmation |
| `add_comment` | Add a comment to an issue | `issue_id`<br/>`message` | None | Created comment ID |

<Note>
Tools that accept `project_id` as optional will infer it from the workspace context if the agent is running inside a linked Wickeban workspace.
</Note>

## Using the MCP Server

Once you have the MCP server configured, you can leverage it to streamline your project planning and issue tracking workflow.

## Example Usage

### Planning and Issue Creation

```
I need to build a user authentication system with the following features:
- User registration with email validation
- Login/logout functionality
- Password reset capability
- Session management
- Protected routes

Then turn this plan into issues.
```

Your MCP client will use the `create_issue` tool to break this down into individual issues and add them to your Wickeban project automatically.

### Duplicate-Safe Issue Filing

Agents connected to the MCP server can check for duplicates before filing:

```
1. ping — confirm Wickeban is reachable
2. search_issues with "authentication timeout" — check for existing issues
3. If match found → add_comment with new stack trace
4. If no match → create_issue_with_context with file path, git ref, and error output
```

### Filing Issues with Structured Context

Use `create_issue_with_context` to provide machine-readable metadata that the planning agent can consume:

```json
{
  "title": "Fix authentication timeout in session middleware",
  "summary": "Sessions expire silently after 30 minutes, no refresh mechanism",
  "repo_name": "my-app",
  "file_path": "src/middleware/auth.ts",
  "line_number": 42,
  "git_ref": "abc1234",
  "command": "npm test",
  "error_output": "Error: Session expired, no valid refresh token"
}
```

This creates a formatted issue description and stores the raw fields in `extension_metadata` for automated processing.

### Internal Coding Agents (Within Wickeban)

A powerful workflow involves using coding agents within Wickeban that are also connected to the Wickeban MCP server:

1. **Create a Planning Task**: Create a task with a custom agent profile configured with a planning prompt. See [Agent Configurations](/settings-beta/agent-configurations) for details on creating custom profiles.
2. **Explore and Plan**: The coding agent explores the codebase and develops a comprehensive plan
3. **Generate Issues**: Ask the coding agent to "create a series of individual issues for this plan"
4. **Automatic Population**: The agent uses the MCP server to populate individual issues directly in the Wickeban interface

This creates a seamless workflow where high-level planning automatically generates actionable issues in your project board.

### Agent Rules for External Projects

If you have coding agents on other projects that should automatically file issues to Wickeban when they encounter problems, see the [Agent Rules for Wickeban MCP](/integrations/mcp-agent-rules) guide for a ready-to-use `CLAUDE.md` snippet.
